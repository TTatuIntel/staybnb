# Staybnb

Booking platform: Next.js web app, Express/Socket.IO API, shared logic package.
Mobile (React Native) is planned; see MOBILE.md.

## Conventions that matter

- **Money is integer minor units** (cents). Never use floats for money. Format
  for display with `formatMoney` from `@staybnb/shared`.
- **Dates are `YYYY-MM-DD` strings**, not Date objects, in API payloads and
  business logic. This keeps stays timezone-independent. Helpers are in
  `packages/shared/src/dates.ts`.
- **Stays are half-open ranges** `[checkIn, checkOut)`. A guest may check in the
  day another checks out. Use `rangesOverlap` rather than hand-rolled comparisons.
- **Business logic goes in `packages/shared`**, not in a client. Pricing,
  validation schemas and date rules live there so web and mobile stay identical.
  The package must not import React, DOM or Node APIs.
- **The server is the source of truth for price and availability.** Clients may
  preview a quote, but `POST /bookings` recomputes both inside the write
  transaction.

## Realtime

`apps/api/src/socket.ts` owns the websocket layer. Anything that changes a
listing's availability must call `publishAvailability`, or viewers will see a
stale calendar. Event names are in `SOCKET_EVENTS` in the shared package, used by
both ends.

## Auth

JWT issued on login. Browsers use an httpOnly cookie; native clients send the
same token as a bearer header. Both paths must keep working, since the mobile
apps depend on the bearer path.

## Gotchas

- The web app's lint config enforces React Compiler rules. Do not call setState
  synchronously in an effect; derive the value during render, or use the
  `useAsyncData` hook for fetch-on-mount.
- Run `npx next typegen` in `apps/web` before `tsc --noEmit` if `PageProps` or
  `LayoutProps` are reported as missing; Next generates those types.
- Prisma client is regenerated by `npm run db:generate` in `apps/api` after any
  schema change.
